# GEO·OPEN 内容更新与发布

网站内容与程序一起保存在 GitHub 仓库中。课程章节采用 Markdown 编写，不需要修改
React 代码。为了兼顾效率与安全，采用两条更新通道：

| 更新类型 | 推荐方式 | 适用内容 |
| --- | --- | --- |
| 日常内容更新 | 直接提交到 `main` | 错别字、段落补充、作业、链接和资料来源 |
| 大型或程序更新 | 分支 + Pull Request | 新增整章、大幅重写、页面程序、依赖和部署配置 |

两条通道最终都会触发：

**提交到 main → GitHub 自动构建镜像 → fnOS 拉取新镜像**

## 1. 内容放在哪里

遥感课程内容位于：

```text
content/
└── remote-sensing/
    ├── 01-introduction.md
    └── _chapter-template.md
```

- `01-introduction.md` 是已经发布的第一章；
- `_chapter-template.md` 是新章节模板，下划线开头的文件不会发布；
- 每个正式章节使用一个 `.md` 文件；
- 文件名只使用小写英文字母、数字和短横线，例如
  `02-electromagnetic-radiation.md`。

## 2. 最快的方法：章节页直接编辑并发布

适合修改错别字、增加一段解释、替换链接或布置新作业。

1. 打开网站中的目标章节。
2. 点击左侧目录下方的 **在 GitHub 编辑本章**。
3. GitHub 会直接打开对应的 Markdown 编辑页面。
4. 在编辑器中修改内容，并使用 **Preview** 检查 Markdown。
5. 点击 **Commit changes**。
6. 日常小改选择 **Commit directly to the main branch**。
7. 填写简短说明并确认提交。
8. 打开仓库 **Actions** 页面，等待 `Publish website container` 变为绿色。
9. 在 fnOS 拉取新镜像并重新部署。

直接提交仍会保留完整 Git 历史，可以查看、比较或撤销。提交前应确认预览、来源与版权
信息无误。

## 3. 什么时候使用 Pull Request

以下情况使用 **Create a new branch for this commit and start a pull request**：

- 新增完整章节或大幅重写现有章节；
- 一次修改多个课程或多份文件；
- 修改网站页面、样式、依赖或部署配置；
- 希望先让他人校稿，不立即影响正式网站。

Pull Request 相当于发布前的校稿页。构建检查通过并完成审阅后，再合并到 `main`。

## 4. Markdown 常用写法

```md
## 二级标题

### 三级标题

普通段落中可以使用 **加粗** 和 [资料链接](https://example.com)。

- 列表项目一
- 列表项目二

> **核心概念**
>
> 这里写需要强调的内容。

| 名称 | 说明 |
| --- | --- |
| 示例 | 表格内容 |
```

编辑时注意：

- 页面右侧目录由 `## 二级标题` 自动生成；
- 章节内部的小标题使用 `###`；
- 不要删除文件最上方两条 `---` 之间的元数据；
- 修改日期后同时更新 `updated`；
- 图片放入 `public` 目录，在 Markdown 中用 `/图片文件名.png` 引用；
- 上传图片前应确认版权、隐私和文件大小，优先使用自己制作或明确可开放使用的材料。

## 5. 新增一章

1. 复制 `content/remote-sensing/_chapter-template.md`；
2. 将副本命名为章节文件，例如 `02-electromagnetic-radiation.md`；
3. 修改文件顶部的 `title`、`chapter`、`summary`、`updated` 和 `keywords`；
4. 按模板撰写正文；
5. 通过 Pull Request 合并。

合并后，课程目录会自动读取新文件并按 `chapter` 数字排序。若目录中仍有同名的
“建设中”占位项，再修改 `app/courses/remote-sensing/page.tsx`，删除对应占位行。

## 6. 在电脑上批量编辑

适合加入整章内容、处理多张图片或先在本地预览。

```bash
git switch main
git pull
git switch -c content/更新说明

pnpm install
pnpm dev
```

浏览器打开终端提示的本地地址。完成编辑后执行：

```bash
pnpm run build:nas
git add content public docs
git commit -m "content: 更新遥感章节"
git push -u origin content/更新说明
```

然后在 GitHub 创建 Pull Request。若修改了网站程序，还应把相应程序文件加入
`git add`，不要机械地把无关文件一起提交。

## 7. GitHub 自动构建发生了什么

仓库中的 `.github/workflows/publish-container.yml` 负责：

1. Pull Request 阶段构建网站，确认 Docker 镜像能够生成，但不发布；
2. 内容合并到 `main` 后，构建 `linux/amd64` 和 `linux/arm64` 两种架构；
3. 发布 `ghcr.io/ismethr/3swiki:latest`；
4. 同时保留 `sha-xxxxxxx` 版本标签，便于回退。

在 GitHub 仓库的 **Actions** 页面看到绿色对勾后，再更新 NAS。

如果希望微信、聊天软件或社交平台分享链接时显示正确的章节封面，可在仓库
**Settings → Secrets and variables → Actions → Variables** 中增加：

```text
SITE_URL=https://你的公开域名
```

填写网站根地址，不要带课程页面路径。下一次构建会把该域名写入分享卡片地址；
未设置时网站仍能正常使用，只是不输出带错误域名的分享图片。

## 8. 在 fnOS 上发布新版本

### fnOS 图形界面

进入 Docker Compose 项目，依次执行：

1. 拉取最新镜像；
2. 重新创建或重新部署项目；
3. 打开网站，检查首页、课程目录和刚修改的章节。

### SSH 命令

在存放 `compose.yaml` 的目录执行：

```bash
docker compose pull
docker compose up -d
docker compose ps
```

浏览器可能保留旧页面。若更新后仍显示旧内容，可强制刷新，或用无痕窗口检查。

## 9. 出现问题时回退

1. 在 GitHub Packages 或 Actions 记录中找到上一个可用的 `sha-xxxxxxx` 标签；
2. 把 fnOS 使用的镜像从 `latest` 暂时改为该标签，例如：

```yaml
image: ghcr.io/ismethr/3swiki:sha-1234567
```

3. 重新拉取并部署；
4. 在 GitHub 中修正内容后，再切回 `latest`。

Git 历史会保留每次教材修改，因此不要通过删除仓库或覆盖整个目录来回退。

## 10. 建议的发布节奏

- 小改动可以随时提交，一个 Pull Request 只处理一个主题；
- 每章正式发布前检查事实、引用、图片版权和移动端阅读；
- 课堂前至少完成一次 NAS 更新与公网访问测试；
- 在提交说明中写清“改了什么、为什么改”，逐步形成教材版本记录。
